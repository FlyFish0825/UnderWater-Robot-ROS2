项目概览与硬件平台

UnderWater-Robot-ROS2 是专为工业级水下机器人（ROV）打造的高可靠、低延迟开源机器人操作系统（ROS 2）软件栈。全栈基于 C++17 实现，运行在 NVIDIA Jetson Orin NX 16GB Super 计算平台上，为水下六自由度姿态控制、双目视觉感知、高精度流体深度闭环和上位机控制提供了完整的工程级解决方案。

💡
初学者核心理解

水下机器人系统的本质是一个“感知 ➔ 决策 ➔ 执行”的闭环回路：下位机 MCU 采集传感器数据上传给边缘主机 Jetson Orin NX；Orin NX 上的 ROS 2 节点解包数据、估算位姿、运行动力分配二次规划算法，再将电机转速指令安全下发给推进器，同时通过以太网向操作手上位机回传高清双目图像与遥测信息。

核心节点（Nodes）全景深度剖析

初学者学习机器人系统，最关键的就是建立清晰的“进程拓扑模型”：明确每一个节点（Node）的输入来源、算法处理、输出目的地以及故障时的降级策略。下面对系统内 10 大核心节点进行全方位的工程级详细拆解：

🔌 1. mcu_gateway_node
包: underwater_mcu_gateway C++17 常驻守护进程

核心职责：整个机器人系统的物理总线中枢与网络网关。负责独占打开与 STM32H750 MCU 连接的 USB CDC 虚拟串口（/dev/ttyACM0），运行有界增量流式解包状态机，向下位机下发电机转速指令；同时在本地开放 TCP 9000（串口透明转发）与 TCP 9002（独占控制权仲裁）端口，供上位机 Qt GUI 无缝接入。

📥 接口总线矩阵 (Topics & Services)
类型接口名数据类型作用与触发条件
发布 (Pub)gateway/framesunderwater_interfaces/GatewayFrame发布校验合法的 AA55/AA58/AA5B 完整二进制帧，供设备层订阅
发布 (Pub)gateway/statusunderwater_interfaces/GatewayStatus汇报串口连接状态、累计收发字节数/帧数、丢包率与缓冲区水位

🧭 2. devices_node
包: underwater_devices C++17 设备抽象层

核心职责：水下传感器的物理语义解释器。它不直接操作硬件串口，而是订阅 mcu_gateway_node 发出的 gateway/frames 二进制数据，将其精准反序列化为工程物理单位，并发布符合 ROS 2 工业标准的传感器状态话题。

📥 接口总线矩阵 (Topics & Services)
类型接口名数据类型作用与触发条件
订阅 (Sub)gateway/framesunderwater_interfaces/GatewayFrame接收网关解出的 AA5B（传感器）与 AA55（电机反馈）帧
发布 (Pub)sensors/imu/stateunderwater_interfaces/ImuState发布九轴加速度（m/s²）、角速度（rad/s）、欧拉角、气压及有效位
发布 (Pub)sensors/depth/stateunderwater_interfaces/DepthState发布水温（℃）、压力（Pa）、计算水深（m）、水面零点 P0 及错误码

服务 (Srv)sensors/depth/zerostd_srvs/Trigger触发水面深度归零校准（将当前大气压采样更新为基准 P0）
服务 (Srv)sensors/imu/calibrateunderwater_interfaces/CalibrateImu触发静止基准姿态采样，保存相对水平/朝向四元数偏移
🔬 核心算法与物理模型：
  • 深度解算公式：$h = \frac{P - P_0}{\rho \cdot g}$，其中 $P$ 为 MS5837-02BA 实测绝对压力，$P_0$ 为水面参考气压（默认 100965 Pa），$\rho$ 为水体密度（淡水 1000 kg/m³，海水 1025 kg/m³），$g = 9.80665\,\text{m/s}^2$。
  • MS5837 状态机高位诊断：当 0x83 状态帧返回异常时，自动拆解 `status` 字段第 24~31 位，定位是 I²C 硬件总线错误、CRC 校验失败还是缺少水面参考。
🎯 3. control_node
包: underwater_control C++17 高安全级门禁

核心职责：六自由度动力分配求解与电机使能安全门禁。接收六轴力/力矩期望（$F_x, F_y, F_z, M_x, M_y, M_z$），通过内置 OSQP 二次规划求解器，计算 8 台推进器的最优推力，并完成死区处理与极性映射；节点内置双重安全锁：必须显式调用服务使能，且具备 500ms 丢包看门狗急停保护。

🛡️ 力矩基准消除虚假耦合： 动力分配严格以推进器几何中心 thruster_center = (-0.012873, 0.0, -0.040532) m 作为计算原点。在平移消除后，纯前进力 $F_x$ 分配将不会产生虚假的下沉力矩，确保 ROV 在水下直线航行时不发生“磕头”或“仰头”。
📷 4. global_cam_pub
包: global_camera C++17 + OpenCV 双目视觉引擎

核心职责：全局快门双目立体相机的硬件采集与网络推流服务。通过 Linux V4L2 接口采集原生 2560x720@30FPS 宽幅双目画面，在内存中按中线零拷贝切割为左目（1280x720）与右目（1280x720），并分别发布标准 ROS 图像；同时内部集成独立 TCP 9001 服务器，支持向下位机或上位机低延迟推送压缩 JPEG 流。

📥 接口总线矩阵 (Topics & Network)
类型接口名数据类型 / 协议作用说明
发布 (Pub)global_camera/left/image_rawsensor_msgs/Image左目 1280x720 原始彩色图像，时间戳严格同步
发布 (Pub)global_camera/right/image_rawsensor_msgs/Image右目 1280x720 原始彩色图像，供立体深度匹配（Stereo BM/SGBM）

🎮 5. manual_control
包: manual_control C++17 人机操控终端

核心职责：终端非阻塞键盘六自由度手动操控交互器。接管终端按键事件（W/S/A/D/I/K/J/L 等），将其转化为六轴档位并保持，首个方向键自动请求使能；支持 preview:=true 隔离安全预览模式，方便在陆上无水环境下进行控制逻辑验证。

📥 接口总线矩阵
类型接口名数据类型作用说明
发布 (Pub)control/manual_requestgeometry_msgs/Twist按 10Hz 持续发布当前按键保持的六轴目标档位（-1.0 ~ +1.0）

🕹️ 常用操控参数：
• preview:=true：只计算推力与发布话题，不调用底层硬件使能服务，安全级别极高！
• auto_start:=false：接入已有正在运行的后台，不自动在后台重复拉起节点。
💾 6. sensors_sub_jilushuju
包: sensors_cpp C++17 10Hz 定频落盘

核心职责：水下试验高可靠定频数据记录仪（数据记录）。以严格 10.0 Hz 采样周期对 IMU 姿态、角速度、加速度、深度计压力、水温与计算深度进行时间戳多源对齐，并自动落盘生成 CSV 文件，存储至工作空间的 Recodes/ 目录下。

📊 数据对齐与完整性规范： 如果某一时刻某路传感器暂时未产生最新样本，该字段在 CSV 中严格写入 NaN，绝不复用历史脏数据或伪造零值；文件首行自动写入标准表头，文件名为生成时刻精确时间戳，完全满足国家级水下实验数据规范。
📈 7. forces_pub
包: manual_control C++17 动力学辨识

核心职责：预定时序水动力学激励信号发生器。在进行水动力学建模、推力拖曳试验或系统阶跃辨识时，按精确时间轴自动发布前向推力 $F_x$ 阶跃信号（默认执行 100 秒后自动请求停机），省去人工按键的不确定性。

🏭 8. backend_host / compat_runtime
包: sensors_cpp C++17 动态库 兼容层架构

核心职责：原项目 14 个兼容入口的统一宿主运行时。原项目中的 depth、sensors_sub、camera_display、auto_control 等命令全部链接至该共享库，运行期根据 COMPAT_ENTRY 宏分派。如果发现系统底层后台未启动，宿主具备进程单例发现与自动后台准备（auto_start）能力。

核心算法解析：八推进器动力分配 (QP Allocation)

机器人六自由度运动（前/后 $F_x$、左/右 $F_y$、上/下 $F_z$、横滚 $M_x$、俯仰 $M_y$、偏航 $M_z$）由 8 台推进器协同驱动。由于推进器数量（8）大于受控自由度（6），该系统属于过驱动系统（Over-actuated System）。本项目采用基于 OSQP 的二次规划算法进行最优推力分配。

📌
力矩基准：thruster_center

本系统严格以 8 台推进器安装坐标的算术平均中心作为力矩基准点，其相对于 URDF 原始 base_link 原点的平移量为：
r_offset = (-0.012873, 0.0, -0.040532) m。 所有推进器的位置矢量在分配计算前均统一减去此偏移量，消除绕底部原点计算带来的虚假俯仰/横滚力矩耦合！

二次规划数学模型与源码核心逻辑

动力分配的目标函数综合考虑期望力跟踪误差最小化与推进器功耗能量最小化：

C++ 核心代码片段：OSQP 矩阵装配与求解 
// internal/underwater_control/src/allocation/thrust_allocator.cpp
// 构建推力配置矩阵 B (6x8): 每一列为推力单位向量与安装位置的力矩叉乘
for (int i = 0; i < 8; ++i) {
    Eigen::Vector3d r = positions[i] - thruster_center_; // 消除原点偏移
    Eigen::Vector3d d = axes[i];                          // 单位推力方向
    Eigen::Vector3d m = r.cross(d);                       // 力矩: r x d
    B.block<3, 1>(0, i) = d; // 线性力 (Fx, Fy, Fz)
    B.block<3, 1>(3, i) = m; // 力矩   (Mx, My, Mz)
}

// 二次规划目标函数: min 0.5 * u^T H u + g^T u
// H = 2 * (B^T * W_v * B + W_u),  g = -2 * B^T * W_v * F_desired
// 约束: u_min <= u <= u_max (推力上下界限幅)
solver.updateHessianMatrix(H_sparse);
solver.updateGradient(gradient);
solver.solveProblem();
Eigen::VectorXd thrust = solver.getSolution();

// 死区与电机方向映射计算:
for (int i = 0; i < 8; ++i) {
    double raw_rpm = (thrust[i] / nominal_max_thrust_N) * max_rpm; // 线性推力-转速映射
    if (std::abs(raw_rpm) < 1000.0) {
        final_rpm[i] = 0; // 落在死区内停机，防止电机低频啸叫或发热
    } else {
        double clamped = std::clamp(std::abs(raw_rpm), 1000.0, 6000.0);
        final_rpm[i] = std::copysign(clamped, raw_rpm) * motor_direction[i];
    }
}

底层串口流式增量解析机制

机器人通过 USB CDC 虚拟串口以 921600 波特率高速传输二进制数据。工业现场中经常面临网络扰动、USB 中断重连、操作系统缓冲区粘包与分片等问题。本项目设计了有界增量流式解析器（Incremental Streaming Parser）。

AA55 帧族（CAN 与电机数据）
格式: AA 55 [BODY_LEN:u8] ... [CRC8:u8] 55 AA
校验: CRC-8 (多项式 0x07, 初始值 0x00)。覆盖从长度字段到尾部前的全部字节。
语义: 承载 CAN 节点反馈（0x201..0x208 电机状态）与下发电机指令（0x100 速度向量、0x11 运行掩码）。
AA58 帧族（网关遥测与流控）
格式: AA 58 ... [CRC16:u16] (总长 20+N 字节)
校验: CRC-16/CCITT-FALSE (多项式 0x1021, 初始值 0xFFFF，小端)。
语义: 汇报 MCU 内部输入/输出 FIFO 队列占用率、CAN RX/TX 负载和硬件状态。
AA5B 帧族（高精传感器遥测）
格式: AA 5B [VERSION=1] [TARGET] [CMD] ...
子命令:
  • 0x80: IMU 原始角速度与加速度 ADC
  • 0x81: IMU 融合姿态欧拉角与状态位
  • 0x82: MS5837 压力与温度数据
  • 0x83: 深度计状态机与 I²C 阶段诊断
  • 0x85: 固件气压组（高度、参考气压、气压值）
⚠️
防粘包与单调重同步原则

若遇到数据截断或校验失败，解析状态机绝不丢弃整个缓冲区，而是将滑动游标仅向后递增 1 字节重新寻找下一个候选帧头（AA 55 / AA 58 / AA 5B）。环形缓冲上限严格锁死在 65536 字节，半包等待超时设为 1.0 秒，彻底杜绝内存泄漏与死锁卡死。

教程 5：上位机 GUI 与控制权协同

本项目支持 PC 端 Underwater_GUI 与板载 Orin NX 双模工作。通过独占控制权协议，彻底解决“上位机操作手与机载自动算法争夺电机”的工业难题：

1
握手连接建立 STATE NANO
上位机 TCP 9002 连接 Orin NX 时，Orin NX 立即回复 STATE NANO。此时控制权属于板载端，上位机初始为只读模式，可监视传感器，但不能向串口发送电机指令。
2
上位机申请接管 CLAIM GUI ➔ OK GUI
操作手在 GUI 界面点击“接管控制权”，GUI 发送 CLAIM GUI。Orin NX 立即停用本地 ROS 2 电机下发并返回 OK GUI。此时上位机获得独占写入权，可经由 TCP 9000 下发原始电机控制指令。
3
释放控制权与断网保护 RELEASE GUI ➔ STATE NANO
操作手点击“释放控制权”（发送 RELEASE GUI）或当网络发生中断时，Orin NX 控制权看门狗自动触发急停保护，安全复位为 STATE NANO，恢复板载控制。

常见故障排查手册 (FAQ)

❓
问题 1：启动提示找不到串口 /dev/ttyACM0 或 Permission denied

原因: USB 线缆松动、未识别，或当前 Linux 用户没有 dialout 串口访问权限。
解决步骤:
1. 运行 ls -l /dev/ttyACM* 查看设备节点是否存在；
2. 运行 sudo usermod -aG dialout $USER 将当前用户加入串口组，重新登录生效；
3. 检查是否有旧进程占用串口：fuser -v /dev/ttyACM0，杀掉残留进程。

❓
问题 2：IMU 数据有效位显示 0，读数全部为 0 或卡死

特别注意（实机血泪经验）: 如果主板上还插着 WCH-Link 下载调试器，WCH-Link 的引脚电平会干扰板载 IMU 串口通信！进行 IMU 验收和正常作业前，必须拔下 WCH-Link 下载器，重启下位机即可恢复。

❓
问题 3：键盘有输入，但推进器完全不转动

排查顺序:
1. 检查启动时是否指定了 motor_tx:=true（默认出于安全考虑是 false 关闭电机输出的）；
2. 检查推力是否落入了 1000 RPM 死区（输入力微小时，系统自动截断为 0 保护电机）；
3. 检查控制权是否被上位机 GUI 占用（若处于 STATE GUI，机载 ROS 指令被硬件锁死拒绝）。
