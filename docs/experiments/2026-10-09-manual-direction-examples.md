# 手动方向修正与经典分配输出

日期：2026-10-09。以下结果由 Nano 当前 C++ 分配器离线计算，未发送实机电机指令。
本记录是该日“六轴整体取反、仍绕原始 base_link”的历史阶段。用户随后明确逐轴方向，
并将基准改为八台推进器中心，当前结果见 [中心基准与正负一档验证](2026-10-09-thruster-center-startup.md)。

## 正方向约定

- 实际 URDF 几何仍使用 NED：+X 北、+Y 东、+Z 地；安装位置和电机极性沿用实际布局修正。
- 用户说明观察方向为从 Z 负侧看模型，并明确要求手动六轴相对原输出整体反号。
- 手动入口 `control/manual_request` 的 Fx、Fy、Fz、Mx、My、Mz 均乘 `manual_input_sign=-1` 后进入分配。
  手动 +Fx 是用户定义的前进（模型 -X），手动 +Fz 是上浮（模型 -Z）。
- 物理力入口 `control/wrench_request` 保持 NED，正 Fz 是向地的模型力，不受手动符号参数影响。
- `motor_direction=[1,-1,-1,1,1,1,-1,-1]` 表示电机的物理极性，与手动输入的全局符号分开。
- 原始操控档位保留在 manual_request，AllocationStatus.requested_wrench 是取反并放大后的 NED 模型请求。

手动 +Fz=1 时只有 5/6 反转，7/8 的目标低于原有 1000 RPM 停机死区，因此产生向上的模型合力，
同时带有俯仰残差；10 档时四台垂直推进器都跨过死区，俯仰仅剩取整残差。
纯 Fx/Fy 的弱垂直补偿也可能落入死区，因此不能把输入单轴等同于死区后严格单轴输出。

## 修改与复现

`manual_input_sign` 只允许 ±1，默认 -1；设为 +1 可恢复原手动 NED 同号行为。
实现位于 allocation.yaml、Config、Allocator::solve_manual 和 control_node 参数读取。
物理 Allocator::solve 函数体和原有几何、极性、比例、死区参数未改。

```bash
source /opt/ros/humble/setup.bash
source install/setup.bash
ctest --test-dir build/underwater_control --output-on-failure
build/underwater_control/allocation_examples
bash tools/validate.sh allocation
```

示例程序每个案例使用独立分配器，输出 36 个 JSON 结果：六轴正负的 1 档、10 档以及物理力案例。
它不启动 ROS、不打开串口。回归测试覆盖六轴取反、状态中的 NED 请求、物理正 Fz 保持向下、
恢复 +1 配置和非法符号拒绝。伪串口集成检查物理 +Fz 前正后负、手动 +Fx 反向以及原有启停门禁。

验证结果：Nano 上 underwater_control 和 underwater_bringup 两个包 RelWithDebInfo 编译通过；
CTest 1/1 通过，`PASS 1618 allocation checks`。伪串口集成通过：物理 Fz=+500 输出
`[0,0,0,0,1757,1757,-1243,-1243]`，手动 Fx=+1 输出
`[1200,-1200,1188,-1188,0,0,0,0]`。
