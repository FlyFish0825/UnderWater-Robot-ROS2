系统信号流图与项目大纲

本页是整份文档的“总骨架”：上半部分用一棵大纲树交代项目由哪些包与目录构成，下半部分用一张端到端信号流图（Signal Flow Diagram）说明数据如何在传感器、下位机、串口网关、ROS 2 话题与推进器之间流动。建议先看懂本页，再进入分层架构（3）与核心节点（4）的细节。

💡
一句话抓住主线

物理传感器 → STM32H750 组帧 → USB CDC 串口 → underwater_mcu_gateway 解包 → underwater_devices 语义化 → ROS 2 话题 → underwater_control 六自由度 QP 分配 → actuators/thrusters/setpoint → CAN 总线下发 8 台推进器。图像与遥测则通过 TCP 旁路直达上位机 GUI。

一、项目大纲结构（Outline）

工作空间按“对外开放业务入口（src/）”与“核心底层实现（internal/）”分区，合计 13 个实际可编译 ROS 2 包：

📦 src/ · 业务与外设入口包 6 包
  • sensors_cpp 兼容层核心：复刻 14 个原命令，sensors_sub 汇总查看、sensors_sub_jilushuju 10Hz CSV 落盘
  • manual_control 终端键盘六轴档位输入、forces_pub 时序激励、preview 隔离预览安全门禁
  • global_camera V4L2 双目采集、左右目拆分发布、内置 TCP 9001 JPEG 推流服务
  • msg_pkg 历史消息接口兼容：ImuData / DepthSensor / Forces / Globalcam / CamPose
  • imu_py 保留原 imu_publisher 命名与使用习惯的轻量入口
  • depth_py 保留原 depth_publisher 命名与使用习惯的轻量入口
🧠 internal/ · 核心 ROS 包 7 包
  • underwater_mcu_gateway 唯一串口所有者：CDC 驱动、AA55/58/5B 增量解包、TCP 9000 转发、TCP 9002 控制权仲裁
  • underwater_devices 设备语义建模：IMU 姿态基准、深度/压力解码、电机反馈解码、SI 换算与过期失效
  • underwater_control OSQP 六轴动力分配、thruster_center 力矩、手动/远程控制权、显式启停与超时保护
  • underwater_description URDF 刚体模型与 base_link → thruster_center 静态 TF
  • underwater_bringup 顶层 Launch：base / manual / monitor / remote_manual / robot / tcp 与记录话题表
  • underwater_interfaces 10 种自定义消息 + 控制权 / IMU 基准服务 IDL
  • underwater_robot 兼容前一版的 C++ 软件心跳节点 robot_node
🗂️ 仓库其他目录 Support
  • docs/Markdown 文档：architecture / interfaces / usage / protocols / hardware / experiments
  • docs/web/本网页版全景说明文档（多页面 HTML 站点，支持离线双击打开）
  • tests/顶级测试中枢索引与一键统一执行脚本
  • tools/ · deploy/辅助脚本与部署文件
  • third_party/第三方依赖（如 OSQP 求解器等）

二、端到端信号流图（Signal Flow）

下图按“由物理到算力、再由算力回到执行”的顺序，逐级标注每个环节的载体、通道与关键信号名。左侧为主干控制闭环，右侧为图像与遥测旁路：

🛰️ 物理感知层
MS5837 深度 / 水温（I²C ~25Hz） 九轴 IMU 原始 / 姿态 / 气压 720P 双目全局快门相机
I²C · UART · USB 采集与组帧
⚙️ STM32H750 下位机 MCU
高频硬件中断、深度计驱动、IMU 数据组装、8 路 CAN 主机、看门狗安全定时器；封装 AA55 / AA58 / AA5B 协议帧。
USB CDC 虚拟串口 · 921600 Baud · /dev/ttyACM0
🔌 underwater_mcu_gateway（唯一串口所有者）
SerialIo 读写与重连 → Parser 增量解包 → CRC/结构校验 → GatewayFrame；单调滑动重同步与旧帧过滤。
gateway/frames · gateway/status · gateway/raw_rx（可选，默认关闭）
解码帧分发（ROS 话题总线，命名空间 /underwater_robot）
🧩 underwater_devices 设备语义层
将字节帧翻译为标准语义：IMU 三组独立有效、深度/压力 SI 换算、电机反馈去重与过期失效。
sensors/imu/state · sensors/depth/state · sensors/* · actuators/thrusters/state
上行测量 + 下行指令汇聚至控制层
🧠 underwater_control 六自由度分配
接收 control/manual_request 或 control/wrench_request，经 OSQP 二次规划分配为 8 推进器推力，叠加死区与极性映射。
control/allocation（QP 推力 / 建议 RPM / 预测六轴量 / 启停状态）
受限内部命令 · 绑定当前串口连接与 enable 会话
🚀 执行机构
actuators/thrusters/setpoint → MCU 校验 0x100 速度向量 → CAN 总线节点 1..8。
8 台无刷推进器 fan1~fan8 · 1000~6000 RPM（含 1000 RPM 死区保护）
◀ 闭环回程：CAN 0x201..0x208 转速/电压/电流/温度反馈回到 gateway → devices
🖥️ 旁路：图像与遥测
双目视觉推流
global_camera 独立打开相机，左右目拆分发布并经 TCP 9001 传输拼接 JPEG，与 MCU 串口相互独立。
原始串口透明桥
TCP 9000 共享唯一串口所有者，向已授权 GUI 透传原始字节（配置/升级协议）。
控制权仲裁
TCP 9002 令牌握手与 gateway/status.control_owner（NONE / NANO / GUI / GUI_MANUAL）互斥仲裁，禁止并行电机输出。
数据落盘
sensors_cpp 的 sensors_sub_jilushuju 以 10Hz 订阅遥测并写 CSV；underwater_bringup 提供记录话题表。
手动控制入口
manual_control 解析键盘六轴档位（-100..100）发布 control/manual_request，0 停机、1 档起步。
🔁
上行与下行不是两条独立总线

上行（传感器遥测）与下行（电机指令）复用同一条 USB CDC 物理链路与同一个网关节点。因此网关是唯一串口所有者：ROS 电机发送、深度命令或 TCP 9000 任一启用时才以读写模式打开串口，三者都关闭时退化为只读；header.stamp 统一表示接收时刻，不是 MCU 采样时刻。

⚠️
关于时间戳与“新鲜度”

所有 header.stamp 均为接收时刻，并非绝对采样时刻。消费方必须检查 fresh / valid / online，不得把历史状态位当作新鲜测量；同时对标准话题设置超时。测量默认 500 ms 过期，心跳 / 状态 2.5 s 过期。

四、控制权与安全信号

信号流的“闸门”由控制权状态与显式启停服务共同把守，确保任意时刻只有一条电机指令来源：

control_owner 含义 允许的电机信号路径
NONE无人持有操作权仅只读监视；任何写串口路径关闭
NANONano 侧 ROS 控制链持有ROS 电机命令（需 manual.launch.xml 且 motor_tx:=true）
GUIGUI 原始串口独占写入禁止并行 ROS 电机输出，仅受独占令牌约束
GUI_MANUALGUI 持有操作权、Nano 执行原控制链Nano 按原控制链下发，权限不要求改回 NANO

关键服务

  • control/enable（std_srvs/SetBool）— 显式启停；启动先停机，每次 enable 必须建立零输出会话，重连后需重新 enable。
  • sensors/depth/zero（std_srvs/Trigger）— 记录空气 / 水面为零点，需 Nano 持有控制权且收到新的有效深度测量。
  • sensors/imu/calibrate / sensors/imu/clear_calibration — 采集或清除已知静止姿态基准，只改主机参考，不向 MCU 发标定命令。
  • gateway/validate_manual_lease — 仅供 9003 适配节点内部校验控制权租约令牌；属可信 ROS 网络内部服务。

安全与失效边界

  • ROS 电机路径只接受已校验的 0x100 速度 / 运行向量；输入或命令超时自动停止。
  • 主机停机依赖链路仍可写，不能替代 MCU 端通信看门狗。
  • 设备数据采用 SensorDataQoS；状态消息使用可靠 QoS；无效数值以 NaN 与 false 有效标志表达。
  • IMU 世界参考系与安装姿态尚未确认，因此未发布设备到 base_link 的 TF，也未启动虚构的定位 / 控制算法。
