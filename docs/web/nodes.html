核心节点（Nodes）全景深度剖析

初学者学习机器人系统，最关键的就是建立清晰的“进程拓扑模型”：明确每一个节点（Node）的输入来源、算法处理、输出目的地以及故障时的降级策略。下面对系统内 10 大核心节点进行全方位的工程级详细拆解：

🔌 1. mcu_gateway_node
包: underwater_mcu_gateway C++17 常驻守护进程

核心职责：整个机器人系统的物理总线中枢与网络网关。负责独占打开与 STM32H750 MCU 连接的 USB CDC 虚拟串口（/dev/ttyACM0），运行有界增量流式解包状态机，向下位机下发电机转速指令；同时在本地开放 TCP 9000（串口透明转发）与 TCP 9002（独占控制权仲裁）端口，供上位机 Qt GUI 无缝接入。

📥 接口总线矩阵 (Topics & Services)
类型接口名数据类型作用与触发条件
发布 (Pub)gateway/framesunderwater_interfaces/GatewayFrame发布校验合法的 AA55/AA58/AA5B 完整二进制帧，供设备层订阅
发布 (Pub)gateway/statusunderwater_interfaces/GatewayStatus汇报串口连接状态、累计收发字节数/帧数、丢包率与缓冲区水位
发布 (Pub)gateway/raw_serialunderwater_interfaces/RawSerial原始字节流镜像（供调试记录或录包分析）
订阅 (Sub)control/motor_commandunderwater_interfaces/MotorSetpoint订阅动力分配节点计算的 8 路电机转速指令，组装成 0x100 帧下发
服务 (Srv)gateway/control_ownershipunderwater_interfaces/ControlOwnership查询或切换控制权所有者（Orin NX 本地 vs 上位机 GUI）
⚙️ 核心参数 (ROS Parameters)
参数名默认值类型说明
serial_port/dev/serial/by-id/usb-...stringMCU USB CDC 稳定设备路径（强烈推荐 by-id 路径，防止插拔后变 ttyACM1）

💡 初学者避坑关键：mcu_gateway_node 必须拥有对 /dev/ttyACM0 的独占访问权限！启动前若有遗留进程未退出，会导致 Failed to open serial port。排查命令：fuser -v /dev/ttyACM0。
🧭 2. devices_node
包: underwater_devices C++17 设备抽象层

核心职责：水下传感器的物理语义解释器。它不直接操作硬件串口，而是订阅 mcu_gateway_node 发出的 gateway/frames 二进制数据，将其精准反序列化为工程物理单位，并发布符合 ROS 2 工业标准的传感器状态话题。

📥 接口总线矩阵 (Topics & Services)
类型接口名数据类型作用与触发条件
订阅 (Sub)gateway/framesunderwater_interfaces/GatewayFrame接收网关解出的 AA5B（传感器）与 AA55（电机反馈）帧
发布 (Pub)sensors/imu/stateunderwater_interfaces/ImuState发布九轴加速度（m/s²）、角速度（rad/s）、欧拉角、气压及有效位
发布 (Pub)sensors/depth/stateunderwater_interfaces/DepthState发布水温（℃）、压力（Pa）、计算水深（m）、水面零点 P0 及错误码
发布 (Pub)actuators/thrusters/stateunderwater_interfaces/MotorState发布 8 台推进器的实际转速、母线电压、工作电流与电调温度
服务 (Srv)sensors/depth/zerostd_srvs/Trigger触发水面深度归零校准（将当前大气压采样更新为基准 P0）
服务 (Srv)sensors/imu/calibrateunderwater_interfaces/CalibrateImu触发静止基准姿态采样，保存相对水平/朝向四元数偏移
🔬 核心算法与物理模型：
  • 深度解算公式：$h = \frac{P - P_0}{\rho \cdot g}$，其中 $P$ 为 MS5837-02BA 实测绝对压力，$P_0$ 为水面参考气压（默认 100965 Pa），$\rho$ 为水体密度（淡水 1000 kg/m³，海水 1025 kg/m³），$g = 9.80665\,\text{m/s}^2$。
  • MS5837 状态机高位诊断：当 0x83 状态帧返回异常时，自动拆解 `status` 字段第 24~31 位，定位是 I²C 硬件总线错误、CRC 校验失败还是缺少水面参考。
🎯 3. control_node
包: underwater_control C++17 高安全级门禁

核心职责：六自由度动力分配求解与电机使能安全门禁。接收六轴力/力矩期望（$F_x, F_y, F_z, M_x, M_y, M_z$），通过内置 OSQP 二次规划求解器，计算 8 台推进器的最优推力，并完成死区处理与极性映射；节点内置双重安全锁：必须显式调用服务使能，且具备 500ms 丢包看门狗急停保护。

📥 接口总线矩阵 (Topics & Services)
类型接口名数据类型作用与触发条件
订阅 (Sub)control/manual_requestgeometry_msgs/Twist键盘手动控制发布的期望六轴速度/档位
订阅 (Sub)control/wrench_requestgeometry_msgs/Wrench自动控制或算法节点发布的标准力与力矩（牛顿 / 牛·米）
发布 (Pub)control/motor_commandunderwater_interfaces/MotorSetpoint最终下发给 8 台电机的目标转速（RPM）与运行掩码
发布 (Pub)control/allocation_statusunderwater_interfaces/AllocationStatus动力分配求解状态（迭代次数、残差、各路分配推力）
服务 (Srv)control/enablestd_srvs/SetBool电机动力输出总开关（发 true 允许电机转动，发 false 强制急停）
⚙️ 核心安全参数
参数名默认值类型说明
motor_txfalsebool全局发送许可。出于安全考虑默认必须通过 launch 显式开启
timeout_ms500int指令超时看门狗阈值。若超过 500ms 未收到新控制指令，自动向推进器下发 0 RPM
deadzone_rpm1000.0double电机死区下限。推力换算转速在 (-1000, 1000) 区间内直接截断归零
max_rpm6000.0double单台水下推进器允许输出的最大转速限制
🛡️ 力矩基准消除虚假耦合： 动力分配严格以推进器几何中心 thruster_center = (-0.012873, 0.0, -0.040532) m 作为计算原点。在平移消除后，纯前进力 $F_x$ 分配将不会产生虚假的下沉力矩，确保 ROV 在水下直线航行时不发生“磕头”或“仰头”。
📷 4. global_cam_pub
包: global_camera C++17 + OpenCV 双目视觉引擎

核心职责：全局快门双目立体相机的硬件采集与网络推流服务。通过 Linux V4L2 接口采集原生 2560x720@30FPS 宽幅双目画面，在内存中按中线零拷贝切割为左目（1280x720）与右目（1280x720），并分别发布标准 ROS 图像；同时内部集成独立 TCP 9001 服务器，支持向下位机或上位机低延迟推送压缩 JPEG 流。

📥 接口总线矩阵 (Topics & Network)
类型接口名数据类型 / 协议作用说明
发布 (Pub)global_camera/left/image_rawsensor_msgs/Image左目 1280x720 原始彩色图像，时间戳严格同步
发布 (Pub)global_camera/right/image_rawsensor_msgs/Image右目 1280x720 原始彩色图像，供立体深度匹配（Stereo BM/SGBM）
网络推流TCP 0.0.0.0:9001自定义二进制流格式：0xAABBCCDD (4B) + 数据长度 (4B 大端) + JPEG 数据
⚡ 性能优化亮点： 图像分割过程基于 cv::Mat 的子区域（ROI）视图实现，不触发整幅画面的内存复制（Zero-copy）。JPEG 编码在独立的工作线程中执行，彻底隔离相机 I/O 阻塞对主控制回路的影响，保证稳定的 25~30 FPS 输出。
🎮 5. manual_control
包: manual_control C++17 人机操控终端

核心职责：终端非阻塞键盘六自由度手动操控交互器。接管终端按键事件（W/S/A/D/I/K/J/L 等），将其转化为六轴档位并保持，首个方向键自动请求使能；支持 preview:=true 隔离安全预览模式，方便在陆上无水环境下进行控制逻辑验证。

📥 接口总线矩阵
类型接口名数据类型作用说明
发布 (Pub)control/manual_requestgeometry_msgs/Twist按 10Hz 持续发布当前按键保持的六轴目标档位（-1.0 ~ +1.0）
客户端 (Client)control/enablestd_srvs/SetBool首次按下方向键时自动向控制节点发送使能请求（preview 模式下跳过）
🕹️ 常用操控参数：
• preview:=true：只计算推力与发布话题，不调用底层硬件使能服务，安全级别极高！
• auto_start:=false：接入已有正在运行的后台，不自动在后台重复拉起节点。
💾 6. sensors_sub_jilushuju
包: sensors_cpp C++17 10Hz 定频落盘

核心职责：水下试验高可靠定频数据记录仪（数据记录）。以严格 10.0 Hz 采样周期对 IMU 姿态、角速度、加速度、深度计压力、水温与计算深度进行时间戳多源对齐，并自动落盘生成 CSV 文件，存储至工作空间的 Recodes/ 目录下。

📊 数据对齐与完整性规范： 如果某一时刻某路传感器暂时未产生最新样本，该字段在 CSV 中严格写入 NaN，绝不复用历史脏数据或伪造零值；文件首行自动写入标准表头，文件名为生成时刻精确时间戳，完全满足国家级水下实验数据规范。
📈 7. forces_pub
包: manual_control C++17 动力学辨识

核心职责：预定时序水动力学激励信号发生器。在进行水动力学建模、推力拖曳试验或系统阶跃辨识时，按精确时间轴自动发布前向推力 $F_x$ 阶跃信号（默认执行 100 秒后自动请求停机），省去人工按键的不确定性。

🏭 8. backend_host / compat_runtime
包: sensors_cpp C++17 动态库 兼容层架构

核心职责：原项目 14 个兼容入口的统一宿主运行时。原项目中的 depth、sensors_sub、camera_display、auto_control 等命令全部链接至该共享库，运行期根据 COMPAT_ENTRY 宏分派。如果发现系统底层后台未启动，宿主具备进程单例发现与自动后台准备（auto_start）能力。

👁️ 9. data_sub
包: global_camera C++17 + HighGUI 图像监视验证

核心职责：ROS 2 双目图像本地订阅与可视化检视工具。订阅 left/image_raw 与 right/image_raw 话题，实时通过 OpenCV 窗口渲染双目画面，并支持键盘按键一键捕获当前立体图像对并保存为 PNG 图片，供标定与离线算法评测使用。

📦 10. depth_publisher & imu_publisher
包: depth_py & imu_py C++17 薄封装 独立单传感器入口

核心职责：单传感器独立调试入口。允许只关心深度计或只关心 IMU 的开发者单独运行 ros2 run depth_py depth_publisher 或 ros2 run imu_py imu_publisher，底层自动挂接 compat_runtime 共享驱动，降低单一传感器故障排查的复杂度。
